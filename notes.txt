JSX: It is a Javascript syntax, which is easier to create HTML elements.
It is a convention where we can combine HTML and Js together.
JSX is not a part of react, JSX is not HTML inside Js.
JSX is HTML-like or XML-like syntax
JSX is just a syntax.
We can write react for large-scale application without JSX also.

Ques: 
Whom are you writing coding for Machines or for humans?
Ans: For both, but primarily for humans because machines can understand binary also,
writing code in a readable way is helpful in understanding code by another 
developer.

Js engine in the browser don't understand JSX.
JSX is transpiled before it reaches Js engine.
This transpiling is done by parcel, parcel is not done by on its own.

Parcel is like a manager, it's cabinet ministers doing multiple tasks like transpiling.

Babel:
Writing a single-line of JSX, it can understand easily. If it is multi-line use paranthesis () to wrap,
so the babel understands there is a JSX code in react.

React components:
1. Class based components - Old way.
2. Functional based components - New way.

React Functional component:
- It is just a normal Javascript Function.
- It is a Function that returns JSX code.
A Function which returning a piece of JSX is a Functional component.

// JSX -> Babel transpiles it to React.createElement ->
// React Element (object) -> When we renders element on DOM that becomes html element.

Component composition:
We're composing component into one another.

const Title = () => (
  <h1 className="title" tabIndex={5}>
    Namaste react using JSX
  </h1>
);

const HeadingComponent = () => (
  <div>
    <Title />
    <p className="paragraph">This is a paragraph component!</p>
  </div>
);

const HeadingComponent = () => (
  <div>
    {/* <Title /> */}
    {title} // title inside the curly braces are sanitized for usage. (Cross-side scripting)
    <p className="paragraph">This is a paragraph component!</p>
  </div>
);
